# 0012. Product Identity as a living description

**Status:** accepted

Context: identity by string failed empirically — of 2,061 enriched listings, 86% sat in (product, condition) cells with fewer than 5 observations; "HP Z440" and "HP Z440 Workstation" split pools; 41% of observations carried unknown manufacturer or condition. String equality cannot fix this because products are amorphous. We decided a **Product Identity** is a persisted row holding a prose description: synthesized by AI from the union of matched listing context, seeded with the user's phrase at Bargain Search creation, rewritten after the first fan-out completes, and retuned from accumulated evidence (rejects, restores, authored descriptions, threshold edits) at checkpoint and on demand. Sift and Enrichment consume the description as the identification context; resolution is inference against it, never string matching. When an identity description changes, existing Sift verdicts are flagged stale rather than silently recomputed — re-sift happens only by explicit re-run, so no hidden model churn lands on the shared inference box (ADR 0006 constraint). Wrong identities are repaired by editing one, or by merge: a single atomic SQLite transaction that re-points every Listing resolution, price observation, Bundle-component membership, and Bargain Search mapping from the losing identity into the winner. This replaces the former `Product` glossary term.
